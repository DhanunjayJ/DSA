

Deriving the time complexity for backtracking algorithms like **Combination Sum** can be a bit tricky because the number of recursive calls depends on the values within the input array, not just its size.

To find the complexity, we need to look at the **State Space Tree** generated by the recursion.

---

### 1. Identify the Factors

Let $N$ be the number of candidates and $T$ be the target value. Let $M$ be the smallest value in the `candidates` array.

* **Branching Factor:** In each call, the `for` loop can run up to $N$ times.
* **Maximum Depth:** The deepest the recursion can go is when we keep picking the smallest element $M$ until we reach the target. This depth is $\frac{T}{M}$.
* **Work per Node:** Inside the loop, we do $O(1)$ work, but when we find a valid combination (`target == 0`), we copy the list, which takes $O(\frac{T}{M})$ time.

### 2. The Upper Bound Calculation

The total time complexity is generally expressed as:


$$\text{Total Time} = \text{Number of Nodes in Recursion Tree} \times \text{Work per Node}$$

* **Number of Nodes:** Since we can reuse the same element multiple times, this is similar to an $N$-ary tree with a height of $H = \frac{T}{M}$. The number of nodes in such a tree is roughly $O(N^H)$, or $O(N^{\frac{T}{M}})$.
* **The "Copy" Cost:** Each time we reach a leaf that satisfies the condition, we perform `new ArrayList<>(temp)`. In the worst case, the size of `temp` is $\frac{T}{M}$.

### 3. Final Complexity Summary

| Complexity Type | Notation | Explanation |
| --- | --- | --- |
| **Time Complexity** | $O(N^{\frac{T}{M} + 1})$ | The exponential growth of the recursion tree plus the cost of copying the results. |
| **Space Complexity** | $O(\frac{T}{M})$ | This is the space used by the recursion stack and the `temp` list. |

> **Note on Sorting:** You included `Arrays.sort(candidates)`. This takes $O(N \log N)$, but since the backtracking part is exponential, the $O(N \log N)$ term is dropped as it is non-dominant.

Because the array is sorted, if a number is too large to fit the remaining target, every number after it will also be too large. While this doesn't change the *worst-case* theoretical complexity, it significantly improves the *actual* execution time in practice.

### The Time Complexity (TC)

The time complexity is **$O(N \cdot 2^N)$**, where $N$ is the number of elements in the `nums` array.

---

### Why is it $O(N \cdot 2^N)$?

1. **The $2^N$ Factor (Number of Subsets):**
For any set of size $N$, there are $2^N$ possible subsets. Even with the `if(j > i && nums[j] == nums[j-1])` check, in the worst case (where all numbers are unique), the algorithm must visit every possible subset.
2. **The $N$ Factor (Copying the List):**
Unlike the previous problems where we only added to `ans` if `target == 0`, here we add the current `temp` list to our results at **every single node** in the recursion tree (`ans.add(new ArrayList<>(temp))`).
* Creating a new `ArrayList` takes time proportional to the number of elements currently in `temp`.
* In the worst case, the list has $N$ elements.


3. **The Sorting Factor:**
`Arrays.sort(nums)` takes $O(N \log N)$. Since $2^N$ grows much faster than $N \log N$, the sorting cost is absorbed into the higher-order term in Big O notation.

### Comparison: Subsets II vs. Combination Sum II

| Feature | Combination Sum II | Subsets II |
| --- | --- | --- |
| **Branching** | $O(2^N)$ | $O(2^N)$ |
| **Termination** | When `target <= 0` or index ends. | When index reaches the end. |
| **Result Storage** | Only at specific leaf nodes. | **At every node** in the tree. |
| **Total TC** | $O(N \cdot 2^N)$ | $O(N \cdot 2^N)$ |

### Space Complexity

The space complexity is **$O(N)$**.

* **Recursion Stack:** The maximum depth of the tree is $N$.
* **Temporary List:** The `temp` list stores at most $N$ elements.
